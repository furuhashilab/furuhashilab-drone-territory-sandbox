## 1. 遊び方（プレイヤー向けの説明）

> この節だけ読めば遊べる、を目標にしています（「マニュアルが必要になったらクソゲー」）。

1. ドローンを飛ばして、飛行ログ（GPX / DJI）を登録する
2. **飛行1分 = 1pt** がチームのポイントになる
3. チームのポイントを使って、キャンパスの建物（ポータル）を占拠・強化する
4. 自分のチームのポータル同士をリンクでつなぎ、3本で三角形を作るとフィールドになり、中のマスがまとめて自陣になる
5. 相手のポータルは攻撃でレベルを下げ、0 にすると中立に戻せる
6. シーズン終了時に、**自陣のマスが多いチームの勝ち**

「あと10分飛べば次のマスが取れる」「相手に抜かれたから今週は飛ぼう」と思えることを一番大事にしています。

## 2. ポイントの貯め方

| 項目 | 値（案） | 説明 |
| --- | --- | --- |
| 飛行時間 | **1分 = 1pt** | 1分未満は切り捨て（`pointsPerMinute: 1`、PoC と同じ） |
| 1日の上限 | **30分まで** | 1人1日あたり、合計30分までをポイントに数える（DJI Neo のバッテリー約2本分） |
| 人数補正 | **3人チームは ×4/3** | 端数は切り捨て（例: 15分 → 20pt） |
| 機体補正 | **全機体 ×1.0** | 今は全員ほぼ DJI Neo なので補正なし。性能差のある機体が入ったら見直す |

### 2-1. 最初から入れるルールと、あとで入れる候補

週報（10/6）の「最初から完璧なポイント制度を考えるより、実際に遊んでから変える」に合わせ、最初のルールは最小限にします。

| 区分 | ルール | 理由 |
| --- | --- | --- |
| 最初から入れる | 1分 = 1pt | 一番わかりやすい |
| 最初から入れる | 3人チーム ×4/3 | チームの人数は最初から決まっている差なので、遊ぶ前に補正しておく |
| 最初から入れる | 1日30分まで | 「長時間飛ばせば勝ち」を防ぐ安全弁。上限がないと、週6日・60分ずつ飛ぶ人が、週2〜3日・15分ずつの人の約10倍のポイントになる（上限30分なら約5倍） |
| 最初から入れる | 二重登録の防止（3章） | 不正やミスを防ぐ |
| 問題が出たら入れる | 今日のフライトボーナス（例: その日最初のログ +5pt） | 「長さより回数」をもっと後押ししたくなったら |
| 問題が出たら入れる | 機体係数（例: 30分級の機体 ×0.6） | Neo 以外の機体が増えたら |
| 問題が出たら入れる | ミッションボーナス（ホバリング・8の字・指定ルートなど） | 軌跡から自動判定できるようになってから。自己申告だと手入力と変わらないため |

## 3. 二重登録・不正の防止

| ケース | 対策 |
| --- | --- |
| 同じファイルを2回アップロード | ファイルのハッシュ値（SHA-256）で判定し、登録済みなら拒否 |
| 同じフライトを GPX と DJI の両方で登録 | 同じユーザーで **飛行時間帯が重なるログ** は拒否 |
| 他人のログを自分の分として登録 | ハッシュ値は全ユーザー共通で判定する（誰かが登録済みのファイルは使えない） |
| 離陸してすぐ着陸したログ | 1分未満は 0pt（登録自体はできる） |
| 時刻が読めないログ・未来の日付 | 解析エラーとして登録しない |
| 屋内で GPS がないログ | **飛行時間が取れれば登録OK**（位置情報は空でよい） |

## 4. ポイントの使い方（コスト）

### 4-1. キャンパス版（Ingress 型）— 推奨

PoC のコストは「デモで3〜12分の飛行」を前提にした値なので、実際の練習量に合わせて **約5倍** にします。
あわせて **フィールド形成ボーナスはなくします**（理由は 5章）。

| 行動 | `RULES` の項目 | PoC の値 | 提案値 |
| --- | --- | --- | --- |
| 開始時のポイント | `startPoints` | 8 | **40** |
| 飛行1分あたり | `pointsPerMinute` | 1 | **1**（変更なし） |
| 中立ポータルを占拠（レベル1） | `capturePortal` | 3 | **15** |
| ポータルを強化（+1レベル、最大4） | `upgradePortal` / `maxLevel` | 2 / 4 | **10** / 4 |
| 相手ポータルを攻撃（−1レベル） | `attackPortal` | 2 | **10** |
| リンクを張る | `linkCost` | 2 | **10** |
| リンクが届く距離（レベル×） | `linkRangePerLevel` | 120m | **120m**（変更なし） |
| フィールド形成ボーナス | `fieldBonus` | 5 | **0**（なし） |
| 自陣の隣の空きマスを取る | `claimCell` | 1 | **5** |
| 相手のマスを奪う | `stealCell` | 2 | **10** |

- **1回（15分）飛べば、ポータルを1つ占拠できる**（またはリンク1本＋マス1つ）。「飛んだらすぐ何かできる」を守るための値です。
- リンク距離 120m は変えません。全21棟の「一番近い建物」までの距離は最大95mなので、どのポータルもレベル1から最低1本はリンクを張れます。
- 攻撃と強化を同じ 10pt にして、守る側と攻める側が同じコストで張り合えるようにします。

### 4-2. B棟9階版（マス目型）

れあらさんが B棟9階の実際の間取りを確認中のため、こちらを使う場合の値も載せておきます（`poc/maplibre-game/` の `RULES`）。
キャンパス版と同じく約5倍にしています（このモードはシミュレーションしていません）。

| 行動 | `RULES` の項目 | PoC の値 | 提案値 |
| --- | --- | --- | --- |
| 開始時のポイント | `startPoints` | 5 | **25** |
| 未取得マスを取る | `costNeutral` | 1 | **5** |
| 相手のマスを奪う | `costSteal` | 2 | **10** |
| 部屋をすべて取ったボーナス | `roomBonus` | 3 | **15**（遊んでみて差が開きすぎるなら 0 に） |

## 5. 数値の根拠（シミュレーション）

キャンパス版 PoC のルール（21棟・リンク・フィールド・182マス、空間ID Z=20）を Python で再現し、
2チームのコンピューターに6週間（42日）遊ばせて比べました。各案40〜50回ずつ。

前提: 1人が週2〜3日、1回15分前後飛ぶ。3人チームは ×4/3。コンピューターは「コストあたりの得が大きい行動」を選ぶ単純な作戦。

| 案 | 飛んだあとポータル操作ができた割合 | 最初のフィールドができる日 | 終了時のマス差 | 判定 |
| --- | --- | --- | --- | --- |
| 約10倍（v0.2） | 約15% | 6週間でほぼできない | 6% | 遅すぎる |
| 約7倍・ボーナスなし | 約50% | 約33日目 | 10% | まだ遅い |
| 約5倍・ボーナスあり（25pt） | 約80% | 約6日目 | **87%**（片方の圧勝） | 雪だるま式に差が開く |
| **約5倍・ボーナスなし（採用）** | **約80%** | **約8〜10日目** | **約10%** | ちょうどよい |
| 約3倍・ボーナスなし | 約95% | 約3日目 | 9% | 速すぎてすぐ飽きそう |

分かったこと:

1. **コストが高すぎると、フィールドがシーズン中にほぼできない**（v0.2 の約10倍案）。1回飛んでもポータルを触れるのは6回に1回程度。
2. **フィールドボーナスがあると、先にフィールドを作ったチームがボーナスでさらにフィールドを作り、差が雪だるま式に開く**。ボーナスをなくすと差は1割前後に収まる。フィールド自体が「マスがまとめて取れる」ご褒美なので、ボーナスは不要と判断。
3. **1日30分の上限は残す**。週6日・45分ずつ飛ぶ人が1人いるチームは、上限30分でもほぼ勝つ（練習した人が勝つのは狙いどおり）が、上限なしだと終了時の差が約2.4倍に広がる。
4. **人数補正 ×4/3 はポイントの量を揃えるだけで十分**。ただし「飛んだ人しかポイントを使えない」作りにすると、4人チームの方が操作する回数が多くなって有利になる（シミュレーションで4人チームが約75%勝った）。**チームのポイントは誰がいつ使ってもよい作りにする**と、勝率はほぼ五分になった。

※ コンピューターの作戦は単純なので、数字は「傾向」として見てください。最終的にはプレイテストで確認します。

→ **「7人で遊べる版」（11月前半）から 12/22 のプレイテストまでの約6週間** で、1〜2週目に最初のフィールドができ、残りの期間で取り合いが続く計算です。

## 6. 勝ち負けとシーズン

- 勝敗は **シーズン終了時の自陣のマス数**（フィールド内のマスも含む）
- シーズンの区切りは、まず「7人で遊べる版の公開 〜 12/22 プレイテスト」を第1シーズンとする案
- チームのポイントは **誰がいつ使ってもよい**（飛んだ本人でなくてもよい。5章の4）。ただし「誰が飛んだか」「誰がどこを取ったか」は記録して表示する（個人の貢献が見えるように）

## 7. 画面フロー

DJI Fly のログはスマホに保存されるので、**スマホで使う前提** で設計します。

```
ホーム（戦況）
  └ ＋ フライトログを追加 → GPX / DJI を選択 → ファイルアップロード → 解析中 → 確認 → 登録完了
                                                        └ 陣地を取りに行く → マップ（ポータル操作）
```

10/6 に出た流れ（フライトログを追加 → GPX / DJI を選択 → アップロード → 解析 → 確認 → 登録 → ポイント → 陣取り）に沿っています。

### 画面1: ホーム（戦況）

PoC のチーム表示（マス・pt・P・F）をそのまま使います。

```
Team A  58マス  320pt  7P  3F
Team B  51マス  280pt  6P  2F
[======== 地図（キャンパス） ========]
今週のチーム: ゆうと 30分 / あき 15分 / …
[ ＋ 飛行ログを登録 ]
```

※ P = 持っているポータル数、F = フィールド数（凡例を画面に出す）

### 画面2: GPX / DJI を選択してアップロード

```
フライトログを追加
ログの種類  ( ) GPX   ( ) DJI
[ ファイルを選ぶ ]
使用機体 [ DJI Neo ▼ ]（前回の機体を自動で選ぶ）
▸ DJI のログがどこにあるか分からない人へ
```

### 画面3: 確認（いちばん大事な画面）

```
10/26  14:02〜14:17   DJI Neo（GPX）
飛行時間  15分20秒
飛行距離  1.2 km（取れた場合）
最高高度  28 m（取れた場合）
[ 飛行軌跡のミニ地図（位置がない場合は出さない） ]
----------------------------------
飛行 15分 × 1pt          15pt
3人チーム補正 ×4/3       +5pt
チームに入るポイント      20pt
----------------------------------
[ やり直す ]  [ 登録する ]
```

登録できないときは「登録する」の代わりに理由を出します。

- 「このログは登録済みです（10/24 ゆうと）」
- 「10/26 14:05〜14:20 のフライトと時間が重なっています」
- 「飛行時間を読み取れませんでした」
- 「今日はすでに30分ぶん登録しています（このログは 0pt）」

### 画面4: 登録完了

```
登録しました  +20pt
チームのポイント 340pt
空きマス（5pt）・強化（10pt）・リンク（10pt）ができます
[ 陣地を取りに行く ]  [ ホームに戻る ]
```

### 画面5: マップ（ポータル操作）

PoC の操作シートと同じ形にします。ポータルをタップすると、できることだけがコスト付きで出ます。

```
B棟  Team A  レベル2  リンク範囲240m  リンク2本
[ 強化する（10pt） ]  [ リンクを張る（10pt） ]
```

- 取れるマス・リンクできるポータルだけを光らせる（PoC と同じ）
- マスやポータルをタップすると「誰が・いつ取ったか」を出す

### 画面6: 履歴（v1.0 では簡易でOK）

- 自分の飛行ログ一覧（日付・飛行時間・入ったポイント）
- 自分が取ったポータル・マス

## 8. 他の担当への依頼

### ② 飛行ログ担当へ（#6 FlightRecord）

ゲーム側で使いたい項目です。

| 項目 | 用途 | 必須 |
| --- | --- | --- |
| `user_id` | 誰のログか・個人の貢献表示 | 必須 |
| `started_at` / `ended_at` | 1日の上限・時間帯の重なりチェック | 必須 |
| `duration_sec` | ポイント計算 | 必須 |
| `source`（`gpx` / `dji`） | 表示 | 必須 |
| `file_hash`（SHA-256） | 二重登録の防止 | 必須 |
| `aircraft_id` | 機体補正（今は全機体 ×1.0） | 必須 |
| `distance_m` | 確認画面 | 任意 |
| `max_altitude_m` | 確認画面・将来のミッション判定 | 任意 |
| `track`（位置の配列） | ミニ地図・将来のミッション判定 | 任意（屋内は空） |

### ① 地図担当へ

- 4章の提案値を `RULES` に入れて遊んでみてほしい
- マス・ポータルに「取った人」と「日時」を持たせたい（`claimed_by` / `claimed_at`）

### ④ 統合担当へ

- `teams` に人数補正（例: `point_multiplier`）、`aircraft` に機体係数を持たせたい
- ポイントの増減は「誰が・いつ・何で」を履歴として残したい（貢献表示と、あとでバランスを見直すため）
