# 統合プロトタイプ（① 地図 × ② FlightRecord × ③ ログ登録）

各担当がそれぞれ作った試作品をつないで、
「飛行ログを登録 → ポイントが入る → B棟9階のフロアで陣地を取る」を1つの画面で通して試せるようにしたものです。
**ルール・レイアウトはすべて仮**で、決定事項ではありません。盤面（B棟9階／キャンパス）は #12 で未決定です。

| ファイル | 盤面 | 元にした ① の PoC |
| --- | --- | --- |
| `index.html` | B棟9階（部屋とマス目） | `poc/maplibre-game/`（main に Merge 済み、PR #11） |
| `campus.html` | キャンパス（建物＝ポータル、比較用） | `poc/ingress-campus/`（PR #14、未 Merge） |
| `experiment.html` | B棟9階（実験用・共有モード） | `index.html` と同じ。claude.ai で公開したときだけ、参加者全員で同じ盤面を共有する |

飛行する場所と陣地は分けて考えます（叩き台 v0.3 0章）。どこで飛んだログでも登録でき、ポイントを使ってフロアのマスを取ります。
## 開き方

`index.html` をブラウザ（Chrome 推奨）で開きます。背景地図（OpenFreeMap・国土地理院の写真）の表示にはインターネット接続が必要です。
背景地図を読み込めない環境（オフラインや claude.ai のプレビューなど）では無地の背景に切り替わり、陣取りはそのまま遊べます。
MapLibre（4.7.1）の JS は cdnjs → jsDelivr → unpkg の順に読み込みを試し、CSS はファイルに埋め込んでいます。
どれも読めなかった場合は、地図の場所に理由とブラウザで開くよう案内を出します。
MapLibre は地図データの処理に Web Worker（別スレッド）を使いますが、claude.ai のプレビューでは Worker を作れません。
その場合だけ、Worker の処理をメインスレッドで動かす代わりの仕組みに自動で切り替えます（`maplibre-gl-csp-worker.js` を追加で読み込む）。
通常のブラウザでは切り替わらず、いつもどおり Worker を使います。

## 読み込めるファイル

形式は ② の `flightparse` と同じく、ファイル名ではなく中身で判定します。

- **GPX**（中身が `<` で始まる）: ブラウザ内で FlightRecord に変換
- **FlightRecord JSON**（中身が `{` で始まる）: ② の `flightparse` の出力をそのまま読む。DJI ログはこの形で登録する
- **DJI の生ログ**: ブラウザでは読めないため、`flightparse` で JSON にするよう案内を出す

## ② の Go 実装と同じ結果になるかの確認

`samples/gpx/synthetic_normal.gpx` を Go の `flightparse` とこの試作品の両方で変換し、
`started_at`・`ended_at`・`duration_sec`（120）・`distance_m`（121.36828687107575）・`max_height_m`（30）・
`file_sha256`（`eeb98ebb…`）・`track`・`warnings` が一致することを確認しました。
`synthetic_no_time.gpx` は両方とも「1 番目のトラックポイントに <time> がありません」のエラーになります。

確認していないもの: 実機の GPX、DJI の実ログを `flightparse` で変換した JSON、Safari / iPhone での表示。

## 制約・注意

- データはページの中だけで、閉じると消えます（Supabase 未接続）
- `user_id` の代わりに、登録画面の「登録する人」の名前で区別しています
- ① と ② のコードをこのファイルにコピー・移植しているため、元のコードが変わったら合わせる必要があります。
  本番では ② の変換をサーバー側（worker）で行い、画面は FlightRecord を受け取るだけにする想定です
- 改ざん（GPX の書き換えなど）は検出できません（② の README と同じ）

## 実験用（`experiment.html`）

`index.html` に「共有モード」を足したものです。claude.ai で公開したページとして開いたときだけ有効になり、
飛行ログの登録記録（`logs`）、マスを取った操作（`moves`）、チーム（`players`）を claude.ai の共有データに保存して、参加者全員で同じ盤面を使います。
盤面とポイントは保存せず、記録を時刻順に並べ直して毎回同じルールで計算し直します（同時に操作しても全員の画面が一致する）。
それ以外の開き方（ファイルを直接開く、GitHub Pages など）では `index.html` と同じく、その端末だけで動きます。

- 登録・操作には、共有メニューで Contributor 以上の権限が必要
- 盤面のリセットはオーナーだけ
- Supabase とは別の一時的な仕組みで、実験用
